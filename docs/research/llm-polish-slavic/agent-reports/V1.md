## Mismatches and open items

No cell value mismatched in this check. Items that are not a clean YES:

1. **C2, gpt-4o-2024-08-06 row.** The fetch returned "89.96 / 88.69 / 73.89 / 72.51" for this row. The values match the claim, but the row came out of a summarised table. Treat it as YES with a note to re-check against the HTML table before publication. The table gives LEK, LEK (en), LDEK and LDEK (en) columns. The claim does not mention LDEK, so this is not a conflict.

2. **C2, number of questions in Table 4.** Not stated in the fetched text. The tool's "13 exams" figure comes from Table 5, not Table 4, so it does not verify the Table 4 subset. Needs the paper's text or caption, or the PDF.

3. **C5, Polish 88.0%.** The source gives "88%", not "88.0%". The value matches at the precision available. The wording comes from the fetch tool's paraphrase, so the quote needs checking verbatim in the PDF before it is quoted.

4. **C5, per-language values for Russian, Ukrainian, Czech, Serbian.** None found in Section 3.1. The only Russian mention is in the Figure 3 caption, which has no numbers. Ukrainian appears only in an o3-mini-high comparison (89% at 128K). Czech and Serbian have no values. The claim cannot be supported from Section 3.1 as written.

5. **C6, row labels.** The table labels the original Bielik row "Bielik 11B v3" and shares the Llama row with "SmolLM3" ("Llama 3.2/SmolLM3"). Values match. The row names in the report should follow the paper.

6. **C6, sample size.** Not stated in the fetched text. Only the sample type (constitution preamble, PL and EN) is confirmed.

7. **C1, Table 7 row labels.** Table 7 header uses "GPT3.5-turbo", "Llama-2-chat", "Llama 2". The fetch tool flagged the "Size/Variant" row as shifted in Table 2 and advised not to rely on it for model sizes. Values in Table 7 were consistent across both chunks.
