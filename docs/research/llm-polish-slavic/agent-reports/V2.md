## Unit of the Petrov CSV numbers

Evidence:

1. README (github.com/AleksandarPetrov/tokenization-fairness): "`tokenization_lengths_validated.csv`: Tokenization lengths where the language-tokenizer pairs with more than 10% characters mapped to UNK tokens removed." The README does not name the unit.
2. Project page (aleksandarpetrov.github.io/tokenization-fairness): "The tokenization length is computed over 2000 sentences from the FLORES-200 parallel corpus."
3. `compute/compute_tokenizations.py` (quoted lines):
   - `data = data_dev + data_devtest`
   - `data_str = " ".join(data)`
   - `tokens = tk.encode(data_str)`
   - `dict_len[tk.pretty_name] = len(tokens)`
   - The script reads from `flores200_dataset`, using dev and devtest splits.
4. Writing the CSV: any language/tokenizer pair where more than 10% of tokens are UNK gets the placeholder "–––". The file is then written with `df.to_csv("assets/tokenization_lengths_validated.csv")`.

Conclusion: the numbers are corpus-level total token counts for the FLORES-200 dev+devtest text, joined into one string per language. They are not per-sentence averages. Caveat: the project page says "2000 sentences", while the code uses dev+devtest (about 2,000 lines in total, so the two agree approximately). Exact sentence counts were not verified. The values are only comparable across tokenizers and languages if the same corpus is used, which it is here.

Note: the number of bytes or characters per language is not in this CSV. Ratios are therefore the only meaningful comparison.

## Mismatch list

1. T4 GPT-4: the claim that the Occiglot post gives Polish fertility for GPT-4 is not supported. Verbatim from the fetch: "GPT-4 is not in the post. It evaluates four tokenizers: Mistral, Llama-2, Phi-2, and Gemma."
2. T4 Llama: the post names "Llama-2", not "Llama". Treat as PARTIAL.
3. T2 Polish premium: the claim that the paper reports a Polish or Slavic premium is not supported by the accessible text. The abstract says only: "The same text translated into different languages can have drastically different tokenization lengths," "with differences up to 15 times in some cases." The project page says: "The tokenization lengths for some lanugages can be more than 15 times longer than English." Neither names Polish or any Slavic language. The arXiv HTML full text (`arxiv.org/html/2305.15425`) returned HTTP 404, so the body of the paper could not be checked. Full text remains COULD NOT CHECK.
4. T3 Bielik label: the table labels the Bielik row "Bielik 11B v3" and the Llama row "Llama 3.2/SmolLM3". The claim's "(Mistral-based)" note and the plain "Llama 3.2" label were not verified in the table.
5. T3 caption: the caption is cut off by the fetch. Only the first part was confirmed: "Comparison of token count, characters per token (CpT), and tokens per word (TpW) for the preamble of the Constitution".
6. T1 reliability: the cl100k values were confirmed in two separate fetches. The other columns (XLM-R, mT5, GPT-2) were seen in only one fetch and are not verified beyond that.

No verbatim mismatches were found in the cl100k_base values or in the Bielik 2604.10799 table.
