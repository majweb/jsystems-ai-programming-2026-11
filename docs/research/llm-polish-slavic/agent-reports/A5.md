# A5 — Vendor model/system cards (iteration 2, merged)

Scope: primary vendor documents and primary tokenizer/benchmark sources for Polish and Slavic languages. Verified 2026-11-24. Method: WebFetch/WebSearch only, HTML or raw GitHub preferred; no downloads or installs. Global-MMLU and MMLU-ProX are owned by A3 and are not reported here (the Anthropic Global-MMLU table and the Gemma 3 Global-MMLU-Lite numbers were dropped for that reason). All benchmark scores are vendor-self-reported.

Headline: Polish is absent from every vendor per-language benchmark table I opened (OpenAI MMMLU, OpenAI o1 system card, GPT-4o tokenizer table, Llama 3.1). Polish appears in two vendor/academic data sources with usable numbers: Aya 23 and Aya Expanse language lists (no scores for Polish), and tokenizer-length data (Petrov et al. CSV; Bielik v3 tokenizer table).

### F8: Petrov et al. tokenizer data (raw CSV): cl100k_base token length, Polish about 1.91x English, Ukrainian about 3.00x
- Source: Aleksandar Petrov et al., "Language Model Tokenizers Introduce Unfairness Between Languages" (arXiv:2305.15425, NeurIPS 2023). Repo: https://github.com/AleksandarPetrov/tokenization-fairness (MIT). Raw data: https://raw.githubusercontent.com/AleksandarPetrov/tokenization-fairness/main/assets/tokenization_lengths_validated.csv
- Data: `assets/tokenization_lengths_validated.csv`: rows are languages (English names, not codes), 27 tokenizer columns including cl100k_base (GPT-4), GPT-2, LLAMA, Qwen, mT5, XLM-RoBERTa, and others. The validated file excludes language-tokenizer pairs with over 10% UNK characters.
- cl100k_base values (raw CSV, read by two separate fetches, same values):

| language | cl100k_base length | ratio to English (derived: value / 52835) |
|---|---|---|
| English | 52835 | 1.00 |
| Polish | 101102 | 1.91 |
| Czech | 111264 | 2.11 |
| Russian | 131496 | 2.49 |
| Ukrainian | 158296 | 3.00 |

- Also in the same row set: English is 52567 for GPT-2/r50k/p50k, so the English baseline varies by tokenizer.
- Units: the CSV header says "tokenization lengths"; the value is not explicitly labeled tokens in the fetched summary. The paper defines premium as the ratio of tokens per parallel sentence to English tokens (FLORES-200). The ratios above are a ratio of totals, not the paper's mean-of-ratios; treat them as approximate.
- Paper abstract (verbatim): "differences up to 15 times in some cases" (paraphrase-free quote from the abstract, fetched); subword tokenizers can differ up to 15x; character/byte-level models "over 4 times the difference in the encoding length for some language pairs."
- Polish included? YES (raw data). Polish is named in the CSV, not in the abstract.
- Verification status: VERIFIED for raw CSV values (fetched twice, same numbers); premium ratios DERIVED by arithmetic and marked approximate. Recommend confirming with a script over the raw file before citing (the fetch tool cannot run code).
- Confidence: high (raw values), medium (ratio interpretation).
